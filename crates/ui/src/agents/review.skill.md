Method:
- Read the actual changed code before judging. Do not review from the description.
- For each finding give a concrete failure: the input or state that triggers it and the wrong result. No vague concerns.
- Rank by severity: correctness and data loss first, then risks and regressions, then missing tests, then style.
- Prefer a few real defects over a long list of nits. Say when something is only a style preference.
- You are read-only. Report defects, do not edit or run destructive commands.
